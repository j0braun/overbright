Read-ahead and the real flow after a reboot: the measurements behind docs/notes/performance/budget.md "A start after a reboot,
the real flow" and docs/developing/read-ahead.md.

The shipping game (built without the developer harness), plus measuring-only log lines (each wait from the key to
the new screen's first frame; every frame over 80 ms), in a window on a private display, keys as a player in a
hurry presses them: Enter as soon as each boot movie takes it, Enter at the title every 0.1 s until its native 4 s
hold lets it through, the profile message, the main menu 1 s, then Career, the garage, "Return to Explore Mode?",
free roam (roam), or Quick Race, a circuit, its options, the car, the transmission question, the race (race).
"reboot": the game folder and the run's own cache folders (the asset cache and the driver's shader cache) dropped
from the OS's file cache (posix_fadvise DONTNEED) before the run; the binary, the driver's libraries and the
kernel stay warm. "first": new cache folders and the game folder dropped. "later": nothing dropped (on this
shared machine other programs evicted part of it between runs: not a clean warm state). "off" / "on":
NFSU2_READ_AHEAD=0 / the default, one build, the runs interleaved.
Columns: the wait's wall ms from the game's log, median [min..max]; the main thread's time in it running (R),
waiting for another thread (S) and blocked on the disk (D), sampled every 4 ms from /proc. The machine was
shared throughout (load average 17-68 on 16 hardware threads, the disk's I/O pressure "full" 2-55 %): the wall
times are upper bounds, the R/S/D split is the trustworthy part.
first = start to the first frame; ealogo/thx/psa/intro = the boot movie opened by Enter (its file read whole on
the main thread); main = the profile message to the main menu's first frame (the garage scene: its platform, the
FE car loaded on a thread the frame waits for); crib = the career garage's first frame; roam = free roam's entry;
carlot / race = Quick Race's car select and the race's entry.
