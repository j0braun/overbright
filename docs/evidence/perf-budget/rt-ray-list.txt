Ray-traced reflections: the rays from a list in a compute pass (docs/rt-reflections.md "The ray list")
Reference desktop GPU (RADV, Vulkan), 3840x2160, the play setup: SSAA 2x, Ray Traced
reflections, Modern + RT lighting, every other row as the player has it (World Detail values incl.).
Base = the tree before this change; new = with it. Shots `--shot <target>` at 3840x2160, bench `--bench`.

1. The target's f16 conversion (a stand-alone wgpu probe, 4 194 304 values: every f16, its f32
   neighbours and the rounding midpoints, random patterns over 2^-30 .. 2^17, the specials)
   fragment export to Rgba16Float: rounds toward zero (0 values off round-toward-zero, 1 986 440 off
   round-to-nearest); compute textureStore to an rgba16float storage texture: the same bits as the
   fragment export for every non-NaN value; only the 5 NaN inputs differ (the export writes 0xFE00,
   the store keeps the payload).

6. Memory: the list is 20 bytes per trace pixel (the pixel, and the march's result for the hits) plus a
   16-byte head, made with the trace's targets: 41.5 MB at 1920x1080, 73.7 MB at 2560x1440, 165.9 MB at
   3840x2160 (the trace is the screen's size at the Ray Traced tier). The bench's own-VRAM peak moved
   +81 / +101 / +146 / +84 MiB (racing / race start / rain / free roam medians) against the list's
   computed 158 MiB; the spread between the runs of one arm is 39-85 MiB (the metric is noisy; the
   computed size is the one to go by).

8. Wave sizes (RADV_DEBUG=shaderstats with every cache off, the race start shot; VOPD = dual-issue
   instructions, wave32 only on this GPU). The world colour shaders of Modern + RT: 168 VGPRs, 9 per SIMD,
   VOPD (wave32): RADV gives every shader with a ray query in it the ray-query wave size (32), and the
   world module holds the NIS characters' ray query (dead outside their pipelines). The list's compute pass:
   96 VGPRs, 4096 bytes of workgroup memory (64 lanes x a 16-entry stack: one query), 16 per SIMD, VOPD
   (wave32); its fragment pass has no ray query (the pixel shaders' default, wave64).
   RADV_PERFTEST=rtwave64 as an instrument (every shader with a ray query in wave64), racing, 4 runs per
   arm, against the wave32 runs of 5. (another series, same settings):
                    frame                main view   trace + rays        characters' bucket
   base wave32      19.02 [18.90..19.21] 6.22        3.17 + 0    = 3.17  1.15
   base wave64      19.17 [19.13..19.20] 6.73        2.53 + 0    = 2.53  1.45
   new  wave32      18.55 [18.43..18.57] 6.26        1.60 + 0.94 = 2.55  1.15
   new  wave64      19.16 [19.12..19.17] 6.73        1.57 + 0.96 = 2.53  1.44

   compute pass the same in both (0.94 / 0.96). The world colour pass is 0.5 ms slower in wave64.
   (wgpu 30 cannot ask for a wave size: it sets VK_EXT_subgroup_size_control's ALLOW_VARYING_SUBGROUP_SIZE
   with its SUBGROUP feature only, no required size.)
