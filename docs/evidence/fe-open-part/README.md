# Animated car mesh bias order

Original executable SHA256: `8f6a9ae2c4cfa01181d2fd755d99c6f4b7103f60273908ea1de1e719dfe2a297`.

The generic animated-part path at 0x62356A–0x6243E5 removes the original
base matrix from the copied mesh, applies the part animation and restores
that base. With column matrices B (original base), M (copied mesh with
world z +0.01), and P (existing ChannelPose.part_matrix), the result is
`B * P * inverse(B) * M`. The previous clone used `M * P`, which incorrectly
left that 1 cm displacement outside the animation. The correction applies
only when a part has an active pose; ordinary meshes and wheels retain their
previous path. Main and reflected bases use the same native sequence.

`native-order.asm` retains the bounded copy/inverse, initial multiplication,
rest-rotation gate, translation, final multiplication and draw-context sites.
The original base is EDI, copied mesh EBX. 0x6235A1 copies EBX; 0x6236F2
multiplies by the inverse of EDI; 0x624194 restores EDI after the animation.
Animated and ordinary body draws retain the supplied body light context.
There is no new 0x48ED60/0x48F660 context calculation in this animated branch;
wheel contexts remain separate. No harmonic or LocalEyePos change is warranted.

## Reproducible original-instruction oracle

`native_matrix.py` reads the original executable, verifies its digest and
constructs a private headless PE probe. It executes the original animated
matrix instructions and original copy, inverse, translation and scalar matrix
multiply implementations. The original executable/assets are never modified.
The original matrix dispatcher pointer 0x803E74 is explicitly set to its scalar
implementation 0x63CEF1; this does not reproduce the game's live CPU dispatch.

The probe substitutes allocation, evaluated animation (0x434190), rest matrix
(0x434460), model origin (0x488E80), door variant (0x434550) and continuation
callbacks. These callbacks supply synthetic inputs, not captured authored
animation data. Original arithmetic ranges and their hashes are retained in
`native-results.json`; no extracted executable sections are committed.
Inputs are quantized to float32 before native execution. The 32 cases cover
PC64 (CW 0x037F) and PC24 (0x007F), main/reflected bases, two animation angles,
and hood/trunk/regular-door/scissor-door branches. Door rotations are synthetic
arithmetic coverage, not a claim about actual authored door axes.

```
NFSU2_EXE=/path/to/SPEED2.EXE NFSU2_PROBE_DIR=/private/output /usr/bin/python3 native_matrix.py
/usr/bin/python3 reconstruct.py /private/output/results.json /private/reconstructed
```

Requires llvm-mc, GNU ld supporting i386pe, Wine and NumPy. The probe uses its
own Wine prefix beneath the output directory and does not launch the game.
`reconstruct.py` regenerates `cases.bin` (32 triples of column-major base,
part pose, native output; each matrix 16 little-endian floats) and
`comparison.json`. Both regenerated byte-identically. Corrected arithmetic
maximum absolute matrix error is 2.50e-7; previous ordering differs by up to
0.006436 metres in translation. The production Rust test allows 2e-6 for
float matrix evaluation differences, and failed before the fix (`red.log`).

## Runtime checks and limits

Release library: 485 passed, 9 ignored. Explicit GPU uniform regression:
981 real RX8/TAXI part draws across LODs and posed wheels/one synthetic opened
part; queued/direct batches identical. Body and wheel lighting expectations
are checked separately. `uniform-gpu.log` and `library-result.txt` retain results.

The release game also rendered real `--shot paint_engine` and `--shot audio`
scenes at 640x480 with 320x240 reflection readbacks; retained hood/trunk PNGs
show the opened parts. Commands use NFSU2_ROOT pointing at read-only original
data, private NFSU2_SHOT_DATA/XDG_CACHE_HOME, NFSU2_HEADLESS_ONLY=1,
NFSU2_SHOT_SIZE=640x480 and NFS_REFLECTION_PNG for the reflection output.
These are draw-path smoke checks, not same-camera native image comparisons.
This evidence establishes matrix order, not complete animation parser,
lighting, timing or image-pixel parity. No performance claim is made.
